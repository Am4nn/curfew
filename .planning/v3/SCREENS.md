# SCREENS.md — The screen inventory and the review gate

Every approved artboard, its route, and a box to tick. This is the contract
between the mocks and the build (decision 74). If a screen ships and does not
match its artboard, that is drift: fix the code, or amend the mock and this row
deliberately.

The canvas lives at `.design/` and is published as an artifact. Artboards are
generated by `.design/build-v3.mjs`, so a change to shared chrome regenerates
everywhere at once.

## The gate

A phase in `PLAN.md` is not done until, for every screen it touches:

1. The route exists and renders in preview mode with seeded data.
2. It has been opened side by side with its artboard and compared: layout,
   spacing, copy, empty state, and the states listed in the Notes column.
3. The box below is ticked, in the same commit as the screen.

No screenshot tooling. A reference capture would be a capture of what was built,
which locks in drift rather than preventing it. A person comparing to the
artboard catches what a diff never would.
